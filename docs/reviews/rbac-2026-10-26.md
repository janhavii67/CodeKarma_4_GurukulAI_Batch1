## 1. Authentication & Session Architecture Overview

### Backend Session Mechanism
- **Session Tokens:** Server-side managed sessions via `SessionModel` in SQLite/PostgreSQL.
- **Token Delivery:** 64-byte cryptographically secure random session tokens delivered exclusively via `HttpOnly`, `SameSite=Lax` cookies (`gurukul_session`).
- **CSRF Defense:** Double-Submit Cookie pattern with readable cookie `gurukul_csrf` compared against `X-CSRF-Token` header on state-changing requests (`POST`, `PUT`, `PATCH`, `DELETE`).
- **Timeouts:** 8-hour absolute timeout; 30-minute idle inactivity timeout enforced on every request.
- **Identity & Permission Resolution:** The `get_current_user` dependency hashes the incoming cookie, validates expiration and revocation, checks `user.is_active`, touches session timestamp, and queries `UserRepository.get_user_permissions(db, user)`.
- **Permission Union:** Combines `RolePermission` (permissions assigned to `user.role_id`) and `UserPermission` (individual permissions granted directly to `user.id`).

### Frontend Identity Mechanism
- **Profile Fetch:** React queries `GET /api/v1/auth/me` upon application mount (`refreshUser`) and immediately after login/registration.
- **Storage:** Identity (`user`) and effective permission strings (`permissions: string[]`) are held purely in React in-memory state (`AuthContext`). Neither role nor permissions are stored in `localStorage` or `sessionStorage`.
- **Client Trust Evaluation:** While the frontend correctly refrains from trusting client-side storage, **route-level guards on child routes are currently absent in `App.tsx`**, permitting any authenticated user (e.g. Trainee) to load Expert pages by URL typing.

## 4. Specific Vulnerabilities Identified

1. **Unauthenticated Audio Streaming (High Severity):**
   - File: `backend/app/api/v1/endpoints/voice.py:236-253`
   - Endpoint: `GET /api/v1/voice/stream/{media_id}` has no `auth_ctx` dependency. Anyone on the network can stream recorded expert audio without authenticating.
2. **Missing Route Guards on Sensitive Frontend Pages (High Severity):**
   - File: `frontend/src/App.tsx:56-61`
   - Child routes `/app/reviews`, `/app/knowledge/new`, and `/app/voice-capture` lack `requiredPermission` or `requiredRole`, allowing unprivileged Trainees to view the authoring and review interfaces upon direct URL entry.
3. **Unfiltered Sidebar Navigation (Medium Severity):**
   - File: `frontend/src/layouts/AppLayout.tsx:96-116`
   - Review Queue (`/app/reviews`) and Voice Capture (`/app/voice-capture`) are rendered indiscriminately for all users, regardless of whether the user possesses `knowledge.approve` or `voice.capture`.
4. **IDOR in Background Job Inspection (Medium Severity):**
   - File: `backend/app/api/v1/endpoints/jobs.py:14-29`
   - `GET /api/v1/processing-jobs/{job_id}` allows any authenticated user to poll any job status without verifying `job.created_by == auth_ctx.user.id`.
5. **Global Dashboard Stats Leakage (Low Severity):**
   - File: `backend/app/api/v1/endpoints/dashboard.py:19-71`
   - `/api/v1/dashboard/stats` calculates and exposes pending review counts and unapproved draft statistics to Trainees who should only see learner-specific metrics.
